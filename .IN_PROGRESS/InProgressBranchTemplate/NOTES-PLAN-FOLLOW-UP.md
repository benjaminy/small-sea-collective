This is a living document for the branch.
When copying this template into a branch folder,
keep the section guidance below until real content replaces it.

# Notes

This section is for anything important to remember for the scope of the branch.
It doesn't need to follow any particular format.
Anything useful can be kept here.
But junk / noise comes at an attention cost, so try to keep it concise.

# Plan

This section is for planning concrete implementation / experimentation steps.

The validation part of the plan deserves special attention.
AIs are not yet trusted to be reliable for serious work,
so the validation story needs to be even better than would be expected on a great software engineering team.
The plan must say how the implementation will convince a smart skeptic that:
1. The goals of the branch have been accomplished
2. The general integrity of the repo (low coupling, maintainability, consistency, etc) has been maintained or improved

As steps are completed, deferred or abandoned, make only brief revisions in this section;
if more substantial discussion or follow-up is required that belongs in another section.

# Follow-up

This section is for specific branch follow-up tasks like creating, modifying or deleting github issues.
General discussion of unresolved questions should go in the Notes section.
