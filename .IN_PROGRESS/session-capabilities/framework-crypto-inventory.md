# Crypto the framework does for apps today

**Repository:** `/Users/benjaminy/Repos/small-sea-collective`  
**Commit:** `b13e8894764fcd6fe7346bdafe51db95eb535769`

An approved app session already gets encryption through ordinary Hub storage calls and can ask the Hub to sign a Git commit.
The Hub keeps the signing private key, but its signing endpoint currently accepts only hard-coded purposes for Files and Core.
Files also uses Cod Sync code that can sign publication links with raw private-key bytes; the current Files calls do not supply that key.

**Minimal capabilities now:** session-bound Git commit signing and reading its public key.
The existing cloud calls should continue to encrypt, authenticate, and decrypt publications implicitly.
App-defined signing purposes can be namespaced by app name, as decided, while the Hub keeps the commit’s team and berth checks.

Two details deserve attention.
The Hub currently hard-codes Files purposes in [backend.py](/Users/benjaminy/Repos/small-sea-collective/packages/small-sea-hub/small_sea_hub/backend.py:973), so framework code knows Files-specific labels.
The optional Cod Sync link-signing API accepts raw private-key bytes; if an app starts using signed links, it will need a session operation before it can do so without holding a framework key.
